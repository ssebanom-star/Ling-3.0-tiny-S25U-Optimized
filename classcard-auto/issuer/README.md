# 인증 키 발급 도구 (컴퓨터용)

앱(0.6.16-dev 이상)은 **이 도구로 발급한 인증 키 파일이 있어야** 실행됩니다. 비밀번호와는 별개의 두 번째 잠금입니다.

## 사용 순서

1. 컴퓨터에 한 번만: `pip install cryptography`
2. 휴대폰에서 앱을 열면 "인증이 필요해요" 화면에 **기기 코드**가 나옵니다.
3. 이 폴더에서 실행합니다.

   ```
   python issue.py --device 3f9a1c2b7d4e8a60
   python issue.py --device 3f9a1c2b7d4e8a60 --days 14     # 14일 뒤 만료
   ```

   `classcard-auth.key` 파일이 만들어집니다.
4. 휴대폰을 USB로 연결하고, 컴퓨터 파일 관리자에서 아래 폴더를 열어 `classcard-auth.key` 를 넣습니다.

   ```
   내장 메모리/Android/data/net.classcardauto.mobile.nocert/files/auth/
   ```

   폴더가 안 보이면 케이블을 다시 연결하거나 휴대폰 화면을 켠 채 "파일 전송" 모드로 두세요.
5. 앱이 몇 초 안에 파일을 읽고 확인한 뒤 **파일을 지웁니다**. 확인이 끝나면 비밀번호 → 사용 안내 동의 순으로 진행됩니다.

## 파일 설명

| 파일 | 용도 | 주의 |
|---|---|---|
| `issuer_private.pem` | 개인키(서명용) | **컴퓨터에만 보관.** 휴대폰·메신저·클라우드에 올리지 마세요. 이 파일이 새면 누구나 인증 키를 만들 수 있습니다. |
| `issuer_config.json` | 공개키와 발급자 ID | 앱에 들어 있는 값과 같아야 합니다. |
| `issue.py` | 키 파일 발급 | 기기 하나당 한 번 |
| `keygen.py` | 키 한 쌍 새로 만들기 | 새 키를 만들면 앱을 다시 빌드해야 하고, 이전에 발급한 파일은 모두 무효가 됩니다. |

## 한계 (솔직하게)

- 인증 키는 **기기 코드·앱 패키지·발급자**에 묶여 있어 다른 휴대폰으로 복사해도 통과하지 못하고, 서명을 위조할 수 없습니다.
- 하지만 앱은 APK 파일이라 코드를 고쳐 이 검사를 없앤 사본을 만드는 것까지는 막을 수 없습니다. 이 잠금은 "인증 없이 설치만으로 쓰는 것"과 "다른 사람 휴대폰으로의 단순 복사"를 막는 용도입니다.
- 이 폴더의 개인키는 앱 제작 과정에서 만들어 전달된 것입니다. 실제로 쓰기 전에 `issuer_private.pem`·`issuer_config.json` 을 다른 곳에 옮겨 두고 `keygen.py` 로 새 키를 만든 뒤, 출력되는 `PUBLIC_KEY`·`MACHINE_ID` 를 `CertificationIssuer.java` 에 넣고 다시 빌드하면 더 안전합니다.

## 컴퓨터 없이 새 휴대폰 인증하기 (V1.8~) — "발급자 휴대폰"

기존 방식(위, 컴퓨터가 키 파일을 만들어 USB로 넣기)은 그대로 쓸 수 있고, 아래 방식을 **추가로 선택**할 수 있습니다.

1. **처음 한 번만 컴퓨터가 필요합니다.** 발급자로 쓸 내 휴대폰에서 앱 > 설정 > 발급자 도구 > `요청 복사`.
2. 컴퓨터의 이 폴더에서
   ```
   python issue.py --issuer-request "복사한 텍스트" [--days N]
   ```
   → `mimic-issuer.cert` 가 만들어집니다. 그 내용을 발급자 휴대폰으로 보내 발급자 도구 2단계에 붙여넣습니다.
3. 그 뒤로는 컴퓨터 없이: 새 휴대폰의 "인증이 필요해요" 화면에서 기기 코드를 확인 → 발급자 폰의 발급자 도구 3단계에 입력 → 나온 **활성화 코드**(약 2200자)를 메신저·메모로 새 폰에 보내 복사 → 새 폰에서 `복사한 활성화 코드 붙여넣기`.

보안 요약
- 발급자 폰의 서명 키는 안드로이드 키 저장소에 있어 앱 밖으로 꺼낼 수 없습니다. 이 키로 서명한 코드는 "컴퓨터가 승인한 발급자 인증서"와 함께 전달되어, 새 폰이 기존 컴퓨터 공개키로 연쇄 검증합니다(별도 재빌드·기존 키 무효화 없음).
- 활성화 코드는 **한 기기·한 앱**에만 유효하고(기기 코드·패키지 묶음), 유효 일수를 정할 수 있습니다. 한번 보낸 코드를 취소하는 기능은 없습니다(유효 일수로 관리).
- 발급자 폰이 도둑맞거나 앱 잠금(비밀번호)이 풀리면 그 폰이 코드를 만들 수 있습니다. 발급자 인증서에도 `--days` 로 만료를 줄 수 있습니다.
- 앱 파일을 직접 고쳐 검사를 없애는 것은 이 방식으로도 막을 수 없습니다.

검증: `python3 tools/auth_roundtrip.py <issuer_private.pem> <android.jar> <kotlin-stdlib.jar>` 가 실제 앱의 CertificateVerifier로 위 흐름(성공·다른 폰·다른 앱·변조·만료·다른 컴퓨터가 만든 인증서·기존 키 파일)을 검사합니다. 안드로이드 키 저장소 부분(PhoneIssuer)은 기기에서만 확인할 수 있습니다.

## QR로 인증하기, 컴퓨터 없이 시작하기 (V1.9~)
- **QR 오가기:** 새 폰의 "인증이 필요해요" 화면에 기기 코드 QR이 나옵니다. 발급자 폰의 발급자 도구에서 `QR 찍어서 기기 코드 읽기`로 찍으면 코드를 입력하지 않아도 됩니다. 발급자 폰이 만든 활성화 코드가 짧은 형식(MC2.)이면 QR로도 나오고, 새 폰은 `QR 찍어서 활성화`로 읽습니다. 앱은 카메라 권한 없이 기기의 카메라 앱으로 사진 한 장을 찍어 읽고, 사진은 읽은 뒤 바로 지웁니다.
- **짧은 코드(MC2.)는 앱에 발급자 폰의 공개키를 넣어 빌드해야 나옵니다.** 길이는 약 610자라 QR로 읽기 쉽습니다. 컴퓨터도 필요 없어집니다(발급자 인증서 불필요).
  1. 발급자로 쓸 폰에서 발급자 도구 > `요청 복사` 를 하면 `"issuerPub":"…"` 가 들어 있는 텍스트가 복사됩니다.
  2. 그 텍스트를 개발 쪽에 주면 `CertificationIssuer.PHONE_ROOTS` 에 `issuerPub` 값을 넣어 다시 빌드합니다.
  3. 새 빌드를 설치하면 그 폰은 컴퓨터 없이 짧은 코드·QR을 발급합니다. (키를 넣지 않은 폰은 지금처럼 긴 코드 MC1.만 만들고, QR은 만들지 않습니다.)
- 앱에 넣은 발급자 키는 되돌릴 수 없는 신뢰 대상입니다. 그 폰을 잃어버리면 앱을 새로 빌드해 키를 바꿔야 합니다.
- `python3 tools/auth_roundtrip.py …` 가 MC2 의 성공·다른 폰·다른 키·모르는 키 id·만료 거부까지 17개 경우를 실제 검증기로 검사합니다.

## 인증용 앱(MiMiC Auth)으로 코드 입력하기 (V1.10~)
짧은 코드를 사람이 입력하는 방식입니다. 새 폰의 앱에 **비밀이 들어 있지 않습니다**(공개키만).
1. 인증용 앱(`MiMiC-Auth-V1.0.apk`)을 내 휴대폰에 설치하고 열면 맨 아래에 "공개키"가 있습니다. `공개키 복사` 후 개발 쪽에 주면 `CertificationIssuer.AUTHENTICATOR_KEYS` 에 넣어 새 MiMiC를 빌드합니다. (처음 한 번)
2. 새 폰의 "인증이 필요해요" 화면 > 방법 C 의 QR을 인증용 앱 `QR 촬영`으로 찍습니다.
3. 유효 기간을 고르고 `코드 만들기` → `3-ABCDE-FGH12` 같은 코드가 나옵니다. 새 폰의 코드 입력칸에 입력(대소문자·하이픈 무관).
- 코드는 **그 QR(그 폰, 그 순간)에만** 통합니다. 다른 폰에 쓰거나 다음에 다시 쓸 수 없고, 30분이 지나면 QR이 새로 바뀝니다. 5번 틀리면 5분 잠깁니다.
- 한계: 앱 파일을 직접 고쳐 검사를 없애는 것은 막을 수 없습니다. 인증용 앱이 든 휴대폰을 누가 잠금 해제한 채 들면 코드를 만들 수 있습니다.
